## Observed Behavior

- The simulation clearly constrains outer-envelope bytes: deterministic CBOR, positional array, definite-length encoding, fixed slot meanings.
- Unknown `pcid` handling is explicit and useful for sparse knowledge: store/forward exact bytes is allowed; speculative payload parsing is forbidden.
- The core scenario ambiguity (map ordering, numeric/string normalization, tags, byte boundaries for a pointer object) is **not** resolved at envelope level; spec explicitly pushes ordering disagreements to the protocol named by `pcid`.
- Payload is opaque bytes until a specific handler is known. Therefore, two conforming implementations can diverge on payload canonicalization unless a payload-level canonical profile exists elsewhere.
- Signature is mandatory but opaque, with algorithm/identity semantics external. If content addressing includes signature bytes, signature nondeterminism can create additional CID divergence pressure unless constrained out-of-band.
- Draft status and no freeze record increase long-horizon risk: future interoperability depends on preserving external payload and signature conventions, not just envelope bytes.

## Verdict

Evidence verdict: Partial agreement only—this simulation proves deterministic CBOR for the **envelope container**, but does not by itself guarantee deterministic CBOR/CID agreement for the **pointer object content** required by this scenario.

- Strengths: good byte-preserving transport boundary, explicit unknown-protocol failure semantics, and no central-registry dependency at envelope layer.
- Weaknesses exposed by scenario pressure:
  - **100-year durability:** bytes may survive, but semantic replay depends on external `pcid` specs and signature ecosystems.
  - **Sparse knowledge:** supported operationally (opaque forwarding), but weak for semantic agreement/audit without handler knowledge.
  - **No central authority:** consistent with scenario; no central registry assumed.
  - **Auditability:** partial; auditors can verify envelope shape but not pointer-object canonicalization without payload spec.
  - **Migration/evolution:** under-specified; no clear rule for canonical-profile upgrades, CID scope stability, or cross-version equivalence.
- Bottom line: this specimen is a solid envelope-layer building block, but it does not satisfy TE-43-style deterministic object-model agreement on its own. A payload-level normative CBOR profile is required.
