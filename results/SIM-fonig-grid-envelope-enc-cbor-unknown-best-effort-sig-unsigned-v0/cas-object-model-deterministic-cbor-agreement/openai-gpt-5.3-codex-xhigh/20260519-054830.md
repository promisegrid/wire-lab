## Observed Behavior

1. **What this simulation covers directly**
   - Defines a positional envelope shape `[pcid, payload]`.
   - Requires deterministic CBOR positional arrays with definite lengths.
   - States canonical bytes for hashing/signing are deterministic CBOR bytes of the exact positional array.
   - Uses fixed byte-string treatment for key slots (`pcid`, `payload`, and signature-related slots when present), which reduces some representational ambiguity at envelope level.

2. **What it intentionally pushes to another layer**
   - Payload is opaque to the envelope; object schema/canonicalization lives under the protocol identified by `pcid`.
   - Layering section explicitly says ordering disagreements are handled by the protocol named by `pcid`.
   - External references and interpretation rules are delegated to payload protocol behavior, not envelope behavior.

3. **Scenario-specific impact (deterministic CBOR agreement)**
   - The scenario asks whether independent implementations produce identical bytes/CIDs for the same pointer object and explicitly calls out map ordering, int/string choices, tags, and byte boundaries.
   - This simulation constrains envelope bytes, but does **not** define pointer-object canonicalization rules inside `payload`.
   - Therefore, two implementations can agree on outer envelope encoding yet still disagree on payload bytes/CID derivation for the underlying object model.

4. **100-year durability pressure**
   - Strength: simple positional envelope is likely re-implementable.
   - Weakness: spec is DRAFT, not frozen, and changelog has no freeze entries; long-horizon reproducibility is not yet anchored by a frozen profile and stable pCID governance for this specimen.

5. **Sparse knowledge / no central authority**
   - Strength: does not require global registry or central authority; local peers can compare raw bytes and known/unknown `pcid` status.
   - Weakness: unknown-`pcid` best-effort inspection yields “unsupported/unverified” outcomes, which preserves local operation but not deterministic semantic agreement.

6. **Auditability and migration pressure**
   - Auditability is weakened by `sig-unsigned-v0`: no envelope-level authorship/integrity proof, so later auditors can inspect bytes but cannot attribute trust without external mechanisms.
   - Migration path is acknowledged (successor variants/freeze gate), but deterministic cross-version object agreement rules are not specified here.

## Verdict

Evidence verdict: **Partial coverage only; insufficient evidence that this simulation satisfies `cas-object-model-deterministic-cbor-agreement` end-to-end.**

The simulation does a useful job constraining deterministic CBOR at the **envelope boundary**, but it defers the core scenario risk (canonical representation of the logical pointer object) to payload protocols. Because the scenario’s key pressure is byte-identical object encoding across independent implementations, and this simulation does not provide those payload-level deterministic rules, it does not resolve TE-43-style “precise CBOR profile” pressure by itself. It is a valid layering specimen, but not a complete answer to this scenario.
