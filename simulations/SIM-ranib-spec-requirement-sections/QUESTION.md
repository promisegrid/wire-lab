# Question

Should PromiseGrid protocol specs require layer-specific promise-vocabulary
sections, 100-year pressure-test sections, and layperson-readable
mental-model / easy-implementation summaries? Source: `DI-pukap`;
`TODO-kulih`; `DR-robon`.

Open decision points:

- Which sections are normative obligations rather than editorial guidance?
- Does every layer need all sections, or should low-level bindings and
  high-level promise protocols have different requirements?
- How much layperson explanation belongs inside the spec rather than in the
  PromiseGrid Development Guide?
- How does a 100-year pressure-test section remain useful without freezing
  speculative implementation details?
- What conformance or review gate checks that required sections are meaningful
  rather than boilerplate?
