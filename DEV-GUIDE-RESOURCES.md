### Current Wire Direction

| Item | Current rule | Why |
|---|---|---|
| Outer envelope | CBOR array `grid([42(pCID), payload, ...])` | Keeps the universal parse surface small while allowing protocol-owned outer growth without inventing new envelope families. |
| Slot 0 | Tagged CBOR protocol selector; tag `42` is the current standard instance | Aligns with the CID / DAG-CBOR ecosystem while keeping the selector rule explicit and bounded. |
| Slot 1 | Primary payload anchor | Gives every receiver one stable protocol-owned byte region immediately after the selector. |
| Slots 2..N | Optional outer slots whose roles, order, and validation rules are defined by the protocol named by `pCID` | Avoids freezing a universal proof/header map too early. |
| Unsupported `pCID` | Preserve exact bytes only as uninterpreted carriage/evidence if local policy allows; do not semantically accept | Carriage is not promise acceptance. |
| Promise wording | "Alice promises this payload and outer-slot arrangement meet the protocol specification named by this pCID." | Keeps Promise Theory vocabulary simple and local. |

Source: `DI-sisak`; `DI-pagin`; `DI-kafiz`.

### Envelope Example

```cddl
; Current wire-lab direction. pCID means Protocol CID.
grid-envelope = [
  selector: 42(pCID), ; tagged protocol selector, current standard instance
  payload: bstr,      ; primary protocol-owned payload bytes
  * outer-slot: any   ; later outer-slot roles are defined by pCID
]
```

Receiver rule:

1. Parse the CBOR array and recover `pCID` from slot 0.
2. If the receiver does not support that `pCID`, it may keep exact bytes as
   carriage/evidence under local policy, but it does not semantically accept or
   reinterpret them.
3. If the receiver supports that `pCID`, it validates `payload` and any later
   outer slots exactly as that protocol specifies.

CBOR array length carries arity. The protocol named by `pCID` defines whether
later outer slots are proof bytes, witness sets, relay evidence, nested
selectors, or absent. Source: `DI-sisak`; `DI-pagin`.

Plain-English explainer: `docs/research/DN-jotob-grid-envelope-tag42-variable-outer-slots.md`
is the short developer note for this current direction. Use it when guide prose
needs the plain-English explanation of why `grid([42(pCID), payload, ...])` is
current, why `42(pCID)` is the present IPLD / IPFS / Bluesky compatibility
choice, and how the immediate `SIM-dalor` / `SIM-pobod` / `SIM-jufag` /
`SIM-zukis` lineage feeds the locked result. `TE-fikoj` / `DI-sisak` remain the
locking authority; `DN-jotob` is explanatory guidance, not a frozen spec.
Source: `DI-sisak`; `DI-bumon`; `DI-zozov`; `DI-hozal`.

### Example Payload Families

Payload structure remains protocol-owned. These examples show the current level
of complexity the guide should prefer unless later scored evidence forces a
heavier universal shape. Source: `DI-pagin`; `DI-kafiz`.

#### Proof-Bearing Payload

```cddl
; Example only. The protocol named by pCID fixes exact fields and proof encoding.
proof-bearing-payload = [
  body: bstr,
  proof: bstr / nil
]
```

Use this when a protocol wants proof inside the main payload rather than in a
sibling outer slot. Source: `DI-sisak`; `DI-pagin`.

#### Promise-Accounting Evidence

```cddl
promise-accounting-evidence = [
  observer: agent-ref,
  subject: agent-ref,
  protocol_pcid: cid,
  evidence_kind: "promise" / "refusal" / "observation" / "timeout",
  observed_bytes: bstr,
  observer_note: bstr / nil,
  signer_proof: bstr / nil
]
```

These are higher-layer local records, not universal base-envelope headers.
Source: `DI-pagin`; `DI-kafiz`.

#### Capability Token as Promise

```cddl
capability-token-promise = [
  promiser: agent-ref,
  promisee: agent-ref / nil,
  promise_body: bstr,
  constraint: bstr / nil,
  proof: bstr / nil
]
```

Treat the token as a promiser's promise, not a global permission object. This
remains active evidence, not a settled final guide API. Source: `DI-pagin`;
`DI-kafiz`.

### Dominant And Alternative Envelope Shapes

| Shape | Status | Strengths | Weaknesses |
|---|---|---|---|
| `grid([42(pCID), payload, ...])` | Current direction | Small universal parse surface; native CID / DAG-CBOR interop; future outer growth without new envelope families. | Later-slot discipline depends on good pCID specs; proof placement remains protocol-owned. |
| `grid([42(pCID), payload, sig])` | Considered, not chosen | Bounded generic parse; obvious sibling proof slot. | Freezes a universal proof-bearing slot too early and duplicates protocol-owned outer-slot semantics. |
| `grid([pCID, payload])` or `grid([pCID, payload, proof])` | Historical predecessor, not current guide shape | Smallest semantic phrasing. | No longer matches the locked tagged-selector outer format. |

Source: `DI-sisak`; `DI-kafat`.
